# Daily Signal

Daily Signal is a dark, responsive cybersecurity explainer site with a daily feature, section filters, site search, individual article views, a source list, and an editorial transparency page. The seven stories in `weekly-news.json` rotate once each per UTC week. This is not a live news service.

Each article uses an original SVG illustration stored in the repository. Images are served locally and do not depend on third-party image hosts.

The wordmark cycles through ten local font stacks in ten UTC time slots. The scheduled workflow records each style change in `current-wordmark.json`, creating one commit for each slot; the first daily update also publishes that day's story. These are cosmetic wordmark changes, not ten new features or news articles.

## Live site

https://news.yashmaheshwari.fyi/

The repository `CNAME` file keeps the custom domain attached to GitHub Pages on each deployment. In Cloudflare DNS, create a `CNAME` record with name `news`, target `serdire.github.io`, and proxy status **DNS only** while GitHub verifies the domain and provisions HTTPS. The `yashmaheshwari.fyi` zone must already be active on Cloudflare nameservers. DNS and HTTPS activation can take time after the record is added.

## Daily publishing

GitHub Actions is scheduled ten times each UTC day, every 2 hours 24 minutes starting at 01:07 UTC. Each successful run checks the weekly stories, updates the selected wordmark style, commits changed edition state to the default branch, and deploys the static site. The first run of each UTC day also selects that day's story and updates `current.json`; the other runs record the logo-style rotations. This uses no AI API key, runtime server, or external content API.

The site is deployed from the repository root using GitHub Actions. The workflow runs the tests on pushes and before its scheduled update. Run the same checks locally with `node --test`; preview the website with any local static HTTP server.

## Add the weekly stories

Before each new week, replace the seven entries in `weekly-news.json` with your reviewed stories for that week, then push the file to `main`. The order is Monday through Sunday (UTC). Each story needs a unique slug, section, headline, summary, reading time, full article paragraphs, takeaways, a primary source URL, an image path from `images/`, and image alt text. Keep claims and source links accurate. The starter stories are evergreen explainers, not current news.

Pushing the weekly file to `main` starts the content checks and site deployment. The scheduled workflow selects that day's story and updates `current.json`; it also updates `current-wordmark.json` for the current font slot. Both files are generated by `node scripts/publish.js` and should not be edited by hand.

Run the checks locally with `node --test`. The checks validate all seven daily story slots, unique routes, required article fields, HTTPS source links, local illustrations, the ten wordmark time slots, and the workflow's ten evenly spaced daily schedules. The ten commits record cosmetic logo-style changes; they do not represent ten separate maintenance fixes. GitHub can delay or skip scheduled runs, so ten commits every day cannot be guaranteed.

## Current scope and limitations

- Seven manually maintained, source-linked stories per week; the starter content is evergreen.
- No live news ingestion, AI-generated writing, accounts, comments, newsletter, or content-management dashboard.
- GitHub scheduled workflows can be delayed or paused, and an automated commit does not guarantee a contribution streak. GitHub's contribution rules, account attribution, workflow availability, and daily execution all matter.
- This is a learning project, not an emergency alert or professional incident-response service.
